## 1. M6B：opt-in 最小身份模式

### 1.1 配置方式

在运行的配置里加入（建议复制 R2 配置后改，不要原地改冻结文件）：

```json
{
  "run_management": {
    "identity_mode": "minimal",
    "run_layout": "timestamped",
    "base_dir": "runs"
  }
}
```

- `identity_mode`：`legacy`（默认）/ `minimal`
- `run_layout`：`legacy`（默认）/ `timestamped`
- `timestamped` 必须搭配 `minimal`；因为 receipt 路径绑定旧 `RL/configs/<RUN_ID>` 布局。
- 可选 `label` 固定目录名；不填则 `runs/<UTC时间戳>_<git短SHA>/`。

### 1.2 行为差异

| 检查 | legacy | minimal |
|---|---|---|
| `require_fresh_operator_experiment` | 执行 | 跳过 |
| `validate_physical_launch`（receipt/runtime identity） | 执行 | **跳过** |
| `preflight_physical_config`（bundle/mode/authorization） | 执行 | 执行 |
| `validate_physical_training_binding`（worker/agent/controller 实际绑定） | 执行 | 执行 |
| `run_meta.json` | 写入现有实验目录 | 写入 `runs/<label>/` |
| 日志目录 | `RL/experiments/<experiment_name>/` | `runs/<label>/` |

> 注意：minimal 模式**没有删除** receipt 代码；只是运行时不再要求它。旧路径随时可切回 `legacy`。

### 1.3 代码位置

- `RL/utils/run_management.py`：`resolve_run_management()` / `apply_run_management()` / `should_skip_launch_validation()`
- `RL/train_rl.py`：启动时应用模式；physical 分支按模式跳过 launch 校验
- `RL/infer/run_bladed_inference.py`：推理侧同样支持 minimal；checkpoint 仍走 SHA 校验
- `RL/run_meta.py`：`run_meta` 记录 `run_management` 字段

### 1.4 启动示例

```bash
# 1) 复制一份配置，加入 run_management 段
cp RL/configs/WT15_STATE20_RL_20261023_R2/state20_physical_23wind_round600_training.json /tmp/minimal_run.json
# 手工在 /tmp/minimal_run.json 中加入 run_management 段

# 2) 预检（仍会检查工件/资源）
conda run -n wind python -m RL.preflight_validation --config /tmp/minimal_run.json --json-out /tmp/preflight_minimal.json

# 3) 启动训练（会写到 runs/<label>/）
conda run -n wind python -m RL.train_rl --config /tmp/minimal_run.json
```

## 2. M7 S2：TurbineProfile

### 2.1 新增文件

- `RL/turbine_profile.py`：dataclass、加载/校验、配置一致性检查、CLI
- `configs/turbines/wt15.json`：15 MW 机型参数与资产路径
- `RL/tests/test_turbine_profile.py`：6 个测试

### 2.2 覆盖字段

- 功率/传动：`rated_power_w`、`gear_ratio`
- 风速：`cut_in_wind_mps`、`rated_wind_mps`、`max_wind_mps`
- 动作：`action_low/high`、`safe_action_low/high`、`action_delta_low/high`、`residual_limit`
- 奖励：`power_ref_w`、`blade_root_ref_nm`、`pitch_rate_limit_rad`、`torque_rate_limit_nm`
- 资产：B4、envelope、S2/U1、BC checkpoint、shadow bundle、paired reference
- 工程：`bladed_project`、`wind_data_glob`

### 2.3 使用方式

在配置中加入（可选）：

```json
{ "turbine_profile_path": "configs/turbines/wt15.json" }
```

训练启动时会调用 `profile.assert_config_matches(config)`；任何额定功率、动作边界、奖励参考或资产路径不一致都会在启动前报错。

也可以单独校验：

```bash
conda run -n wind python -m RL.turbine_profile \
  --profile configs/turbines/wt15.json \
  --config RL/configs/WT15_STATE20_RL_20261023_R2/state20_physical_23wind_round600_training.json
```

实测输出：`turbine profile matches config: wt15`。

## 4. 已知限制与风险

1. **minimal 模式未在真实 Bladed 上验证**：本次只有代码与离线测试；上机前必须用 4×4 验证。
2. **receipt/validator 代码仍在**：M6B 是“opt-in 跳过”，不是硬删除；真正的删除留给后续人工批次。
3. **DLL 环境变量未动**：Windows 侧 `RUN_ID`/`QUEUE_EPOCH`/`CONDITION_INSTANCE_ID` 仍按旧流程；minimal 模式只影响 Linux 侧校验与目录。
4. **31 个旧 identity 测试被跳过**：如果去掉 `WT15_M6_TRANSITION=1`，它们仍会因 R2 pinned runtime 哈希变化而失败；这是过渡期的预期状态。
5. **22 MW 未实现**：profile 结构已就位，但无 22 MW 工程/数据，不能声称支持。
6. **默认仍是 legacy**：不会改变现有 R2/4×4 的行为；要启用新流程必须显式加 `run_management`。
