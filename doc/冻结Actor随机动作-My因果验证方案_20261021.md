## 2. 因果问题与估计对象

### 2.1 主要估计对象：随机分配的意向处理效应（ITT）

处理定义为：在预先规定的有效 TRAIN 决策点，将一个经工程批准的 torque-only 或 pitch-only 请求偏移，加到冻结 Actor/B4 原请求上，随后仍经过**全部既有**保护、投影、速率限制和 wire 序列化。对每个 treatment arm 与 sham 比较随机分配所导致的 My 响应差异。由于保护链可能衰减或拒绝偏移，ITT 是“分配到该受保护处理”的效应，不等于裸执行器增益。

在动作原点 $t$，当前 UDP 帧和 $My(t)$ 是发送动作前观测；随机分配的动作从该帧发送，首个后续载荷观测为 $t+0.02$ s。按叶片分别定义一个预注册主结果：

$$
Y_{b,H}=\max_{1\le k\le H/0.02}|My_b(t+0.02k)|-|My_b(t)|.
$$

对处理臂 $a$ 相对 sham 的目标量为：

$$
\tau_{a,b,H}=\mathbb{E}[Y_{b,H}\mid Z=a]-\mathbb{E}[Y_{b,H}\mid Z=\mathrm{sham}],
$$

在已注册的 wind × 风文件/种子 × 运行状态/时间块内估计并报告。$H$、主 blade 结果汇总规则和最小有意义差异须在随机化前由工程/试验负责人确定；不能看完新试验结果后再挑选。

次要结果包括预注册滞后网格上 $|My_b(t+h)|-|My_b(t)|$ 的随机组间差、窗口内每片叶片峰值/峰值时间、首次越过名义 PID 峰值的情况、扭矩/桨距最终成功 wire demand，以及功率和保护介入。三个 blade 必须分别报告，不能用平均载荷掩盖单片峰值。

此 estimand 是**冻结 Actor 闭环中插入一个受保护 pulse 的总效应**：pulse 后 Actor 仍根据新观测输出后续动作，因此后续 Actor/执行器/保护响应属于总效应的一部分。它不是“固定其它后续动作后的结构直接效应”，也不是可移植的裸 actuator gain。若研究目标改为直接执行器响应，需另行设计不同的控制策略与 estimand，不能从本设计中事后分解。

### 2.2 严格区分“随机分配效应”和“实际送出剂量效应”

- 主要分析按随机分配的 treatment arm（ITT）进行。**不得**因投影、rate limit、pitch protection、fallback 或 My 结果而删除已随机分配的样本。
- 逐帧记录分配偏移、保护前请求、保护/投影/限速后动作和精确 wire demand，以检查 manipulation/first stage。若 wire demand 没有形成可区分的剂量，只能报告“该受保护分配策略未产生足够动作对比”，不能称为已估计裸动作响应。
- 实际执行剂量与 My 的关联仅为次要描述。若未来要用随机分配作工具变量估计每单位 wire demand 效应，须另行预注册并论证排除限制、单调性等假设；不可直接用 treatment 后的 wire demand 回归替代随机化主分析。

随机试验的有效样本单位是独立 reset 的 Bladed trial episode/预先定义的随机化 block。20 ms 帧、重叠观察窗和 blade 读数不当作独立随机样本。

## 3. 随机化设计

### 3.1 五臂、单执行器、固定时长

第一轮不测试 torque 与 pitch 组合项。每个已批准的随机化 block 包含：

| arm | 处理请求 | 说明 |
|---|---|---|
| sham | 零偏移 | 使用同一资格检查、事件标记、日志和安全执行路径，不改变冻结 Actor 请求 |
| torque+ | $(+\Delta_T,0)$ | 只加 torque 请求偏移 |
| torque− | $(-\Delta_T,0)$ | 只加反向 torque 请求偏移 |
| pitch+ | $(0,+\Delta_\beta)$ | 只加 pitch 请求偏移；正方向含义须按工程定义核实 |
| pitch− | $(0,-\Delta_\beta)$ | 只加反向 pitch 请求偏移 |

所有 arm 使用相同、固定的 pulse 持续步数 $K$；处理结束后偏移归零，Actor 按原策略继续运行。$\Delta_T$、$\Delta_\beta$、$K$ 和后续观察/洗脱时长目前均**未设定**，须经工程审批，不从 v10 相关、Q25 分位数或 003 的单次越线动作反推。

### 3.2 随机化单位和配对

推荐采用**单个随机化 pulse / 独立 reset episode**：每个 episode 最多实施一个 pulse 或 sham，降低同槽多 pulse 的 carryover。随机化 block 预先按以下信息分层：

1. wind condition 与实际工程 case / 风文件 / 湍流种子；
2. 预先指定的仿真时间窗和允许的 control region；
3. pulse 前已观测状态/载荷分层（仅使用动作发送前变量）；
4. 重复编号/独立 Bladed reset。

每个 block 内对五个 arm 做平衡随机分配并随机化运行顺序。优先复用同一确定性风文件/种子和相同初始条件，使各重复在 pulse 前尽可能相同；实际工程、风文件和种子须记录并由操作员确认。若不能保持同一 case/seed，应按实际 identity 分块并将其限制写入结论。一个 seed 的随机试验只证明对该 seed/仿真 case 的条件效应；跨种子推广需要额外预注册的 seed 重复。

随机化算法、seed、分层和候选 schedule 在运行前预注册并哈希绑定；assignment 对操作员/控制逻辑保持隐藏。每个独立 episode 先按预设时间窗执行相同的 frozen-Actor/sham 前置运行；达到资格条件后才揭示该 block 内预先生成的 balanced assignment，并在该次 episode 最多实施一个 pulse。这样可避免操作员按即将执行的 arm 挑选状态或时点。记录计划与实际 assignment、随机化 seed/算法版本、block、episode、资格时间、arm 和 manifest SHA-256。未达到资格的 trial 记 screen-failure，不揭示 arm；原因和 count 均报告。已揭示/分配后发生保护、投影或限速，则保留在 ITT，不得改签或按结果删除。

### 3.3 资格检查必须先于揭示 treatment

只有同时满足预注册条件时才进入随机化：queue phase 为 TRAIN；当前/下一帧有效且连续；condition/instance/epoch/frame/time 身份闭合；冻结 Actor 正常执行；动作原点满足工程批准的运行状态和载荷裕量条件；pulse 前没有已激活的禁止性 fallback/保护状态；动作边界、速率余量和总暴露预算允许进入试验。

资格变量全取自当前帧和此前历史，不能按未来 My、pulse 后保护结果或同槽最终峰值入选。若只在“低载荷”状态估计，必须使用工程预先批准的 $M_{\mathrm{entry}}$ 或状态规则；它不是结构安全证明，禁止以事后 Q25 代替。wind11 的已观察越线风险较高，应只在工程负责人批准且满足同一前置资格时才进入随机 treatment；不满足条件时可保留 sham/基线观察，不能为追求 treatment 数强行入选。

## 4. 动作注入与现有控制链

当前代码每步先由确定性 Actor 产生 policy residual，再由 `SafeResidualController` 决定执行模式、fallback、pitch/low-speed protection、边界和速率投影，最后由环境序列化并发送。当前 Round4 推理准备器固定要求 **4 wind × 1 round × 600 s = 4 slots**，没有 treatment/sham assignment 能力。因此不得把普通 003 inference config 当作随机试验配置；需要新增独立随机试验 route/schema 和多 slot schedule。

实现时只允许在冻结 Actor/B4 产生的**物理 action request 与既有保护/投影之间**加入分离记录的外生偏移。偏移必须继续通过：

1. Actor-active / execution-mode 资格门；fallback 时不绕过原有控制模式；
2. 现有 pitch protection、low-speed/other protection；
3. action absolute bounds、rate limit、projection；
4. 环境最终 `PhysicalActionTransform` 检查和六位小数 wire 序列化。

严禁在 safety/projection 后、UDP 字节层、Bladed DLL 或保护参数上加偏移，严禁关闭/放宽保护，严禁让处理越过工程设置的动作/速率范围。实验信号与 Actor residual 必须分列记录，不伪装成 Actor 的动作。Sham arm 在同样软件路径上加零偏移；对相同输入的离线回归测试必须证明它与原冻结路径的最终 wire 字节一致。

## 5. 必须补齐的记录

现有 step CSV 已记录 policy residual、保护前动作、保护/投影/限速结果、sent action、frame/slot/time 和控制介入。但当前推理表没有 treatment assignment 字段；环境内部虽保留最后一次成功序列化的六位小数 wire demand，仍须把它与同一行 frame/slot 一起持久化。随机 trial 至少需要：

- `trial_id`、`block_id`、`condition_id`、`condition_instance_id`、`queue_epoch`、`frame_id`、simulation time、pulse 起止帧；
- `randomization_manifest_sha256`、assignment arm、随机化 seed/算法版本、资格判断和未入组原因；
- 计划 actuator、正负号、审批过的 request offset、pulse elapsed step；
- 冻结 Actor checkpoint SHA、control contract fingerprint、B4/profile SHA；
- 无偏移的 frozen Actor/B4 requested action、perturbed requested action、保护后动作、projected/rate-limited action；
- 最终已成功序列化的 `wire_action_torque` / `wire_action_pitch`（六位小数原值）、实际与未扰动请求的差值；
- 每个保护/投影/限速/fallback/unsafe-stop 标志、invalid/timeout/frame gap，以及三片 signed My、状态、风速和功率；
- pulse 后预注册的观察窗结果、drop/skip 原因、slot 完整性和 T1 结果。

主要因果分析使用完整逐步记录，不依赖 003 中已饱和且丢弃候选的事件窗。原始 Bladed payload 的 My 是当前帧观测；行内 action 是该帧后发送的动作；按 frame ID 对齐未来 My 时不得错一帧。

## 6. 试验阶段与门禁

### 阶段 0：预注册与工程批准（不启动 Bladed）

逐项填定并签核：允许的 wind/case/seed；可测试的 operating state / region；$\Delta_T$、$\Delta_\beta$；$K$ 与观察窗 $H$；洗脱时长；绝对载荷/变化率/转速/功率等 stop rule；每 slot 最大 pulse 数和累计暴露预算；主要 estimand、最小有意义 My 差异、置信度/多重比较规则；允许的工程动作边界和保护未通过时的中止路径。PID 峰值只作为历史描述参考，不充当安全界。

### 阶段 1：实现和离线回归（不启动 Bladed/UDP）

建立新 route，不改旧 `001/002/003` receipt；生成 schedule 和 SHA；加入 treatment/sham 字段及精确 wire log；增加以下单元/合成测试：arm 分布/seed 可复现、资格门在随机化前、一次性 pulse、episode 重置、偏移只进批准 action channel、所有保护仍先于发送、投影/rate limit 正负例、fallback 时不绕过保护、处理后 clip 仍留在 ITT、wire six-decimal frame identity、sham byte-identical、无效/END/skip/重复 slot 的拒绝。

### 阶段 2：无随机扰动的时序/T1 资格 run（新 RUN_ID）

使用冻结 Actor、sham/零偏移和新日志跑经批准的短 qualification 批次。先证明 20 ms grid、frame/time/action 对齐、TRAIN/END 完整收尾、无缺失 treatment/wire 字段、schedule/receipt SHA 闭合；T1 输出频率达到当前 50 Hz 门槛。003 的 25.961 Hz 失败是未解决的先决条件。若此阶段 T1 或日志/身份门禁失败，停止，不在同一批中试随机动作。

### 阶段 3：随机化可行性 pilot（单独新 RUN_ID）

只在阶段 0 批准的安全状态和剂量下，执行五臂随机 pilot；不升级剂量、不根据已看到的 arm 结果在线调整。验证随机 arm 在资格通过后实际产生可区分 wire demand，保护全程工作，My/风/状态无缺帧且停止规则可执行。pilot 主要用于安全、first-stage、数据质量及功效设计；除非预注册为确认性试验，不得把 pilot 结果包装成最终验证。

### 阶段 4：确认性随机试验（再次使用全新 RUN_ID）

根据 pilot 预先完成 block/seed 层级功效或精度计算，锁定 arm 剂量、窗口、block 数、排除规则和分析脚本；生成新 schedule/hash 后才揭示/运行。确认性数据与 pilot 分目录、不同 RUN_ID；禁止一边看结果一边改剂量、stop rule、分层或主结果。

## 7. 分析方案

1. **完整性先行：** 按新 RUN_ID、condition/instance/epoch/frame 检查 randomization manifest、实际 slot 顺序、每条分配和 wire send 闭合；缺帧、未成功发送、schedule 错配等状态独立报告，不能静默删样本。
2. **主 ITT：** 在预注册 block 内比较四个 signed 单执行器 arm 与 sham 的每 blade $Y_{b,H}$。按随机化方案做 block-conditional estimate / randomization inference；不把 20 ms samples 当 $n$。报告效应量、置信区间和每个 wind × blade 的方向/异质性。
3. **滞后响应：** 对预注册 $h$ 网格比较未来 My 变化，给同时置信带或预先指定的多重检验校正。重复窗口、同一 episode/seed 的相关性按 episode/seed 聚类或通过 randomization inference 处理。
4. **处理实现度：** 对比分配 arm 与六位 wire action 实际差异；逐类报告被 protection、projection、rate limit、fallback 衰减/阻断的比例。主 ITT 不按处理后的“成功扰动”筛选。
5. **PID 参照：** 可报告整槽每叶片峰值与名义 PID reference 的比例，但 003 已知 strict case match 0/4；除非新 run 的 reference identity 合同独立闭合，否则这一项只能作为开发描述，不能冒充严格 PID paired 效应或安全阈值。
6. **可推广范围：** 结论限定在实际随机化覆盖的 wind/seed/state/dose。只有一个 turbulent seed 时写明“条件于该 seed”；若要外推，确认性试验需预先加入额外独立 seed/工程 case。

## 8. 预设停止与无效判据

- 所有既有保护保持原样。任何 unsafe-stop、engineer-defined hard stop、通信/时间网格失配、非有限输入、action/wire identity 不闭合，立即停止后续 pulse，并按操作批准的流程结束/保留当前 episode；已分配观测保留在 ITT/安全报告中。
- 触发一般 projection、rate limit 或 pitch protection 时，不把此样本从 ITT 删除；停止后续处理是否继续由阶段 0 的安全审批决定，并记录实际剂量变化。
- 若 T1 未达门槛、manifest 缺失/哈希不符、冻结 Actor 不一致、实际工程/风文件/seed 未确认、wire demand 未落日志，随机试验不得启动或不得给出因果结论。
- 发生严重偏离时保留失败 RUN_ID 与原始数据，不覆盖重跑；修复后使用新 RUN_ID 和新 receipt。

## 11. 可支持与不可支持的结论

若随机化、预处理资格、记录和分析均按预注册方案闭合，结果可支持“在本次 Bladed 模型、所选工程/种子/状态和受保护动作链下，随机分配某一 torque-only 或 pitch-only 请求偏移导致了某种 My 响应差异”的因果结论。

它仍**不能**证明真实风机上的同等效应、跨风种子/工程的普遍规律、My 不会越过 PID 峰值、物理 shadow 可安全干预、Actor 已验收或 soft/hard 具备授权。随机化试验的因果结果与策略性能/安全资格是不同证据门。

**建议的下一动作：先评审并填完第 10 节的工程参数，再开发独立 trial route 和离线测试；随后只跑新 RUN_ID 的无扰动 T1/sham qualification。未通过 T1 或安全审批前，不启动随机化 Bladed pilot。**
