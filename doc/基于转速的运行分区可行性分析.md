# 基于转速的运行分区可行性分析

**日期：2026-10-23**  
**范围：**只读分析 `bladed-data-new/raw` 的 23 条 PID trace；未改动分类器、canonical 工件、profile、release、receipt 或授权，也未运行训练/Bladed。

## 1. 问题定义

当前的 `below_rated / transition / above_rated` 是供 B4、BC residual 和状态条件 reward 使用的**控制运行区**，不是超速安全状态。现有分类器使用 2 s 因果风速 EMA：首帧按 enter threshold 初始化，后续切换要求候选区间持续 1 s；threshold 是 transition 进入/退出 11.8/11.2 m/s、above-rated 进入/退出 13.8/13.2 m/s。[当前阈值配置与顺序校验](../RL/utils/operating_state.py#L51-L89) [初始化、滞回和持续确认](../RL/utils/operating_state.py#L205-L253)

用户给出的 $1.12\,\omega_{rated}$ 算法停机和 $1.20\,\omega_{rated}$ 外层安全链停机，应视作**独立的超速保护事件/保护层**，不能直接等价为 below/transition/above 三个控制区。

## 2. raw 数据与方法

- 读取 raw 中 condition 3–25 的全部 CSV，共 690,023 行（每个 condition 30,001 个 20 ms 样本）；没有读取 `raw_infer`，也未用 holdout 选阈值。
- 用现有 `OperatingStateClassifier` 按滤波风速为每行生成对照标签。运行/发电样本 665,903 行：below-rated 242,330 行，transition 66,560 行，above-rated 357,013 行。
- 将现有 wind-defined region **仅作为对照标签**，在训练的 22 个完整 condition 上拟合两个转速阈值，再对留出的整个 condition 测试。此结果回答“转速单变量能否复制当前风速分区”，不证明风速标签是真实机械模式的 ground truth；如果风速 trace 时间错位，当前标签本身也可能有系统误差。

## 3. 结果

### 3.1 各 wind-defined region 的 raw 转速分布

| wind-defined region | 样本数 | rotor speed P05 | 中位数 | P95 |
|---|---:|---:|---:|---:|
| below-rated | 242,330 | 0.5100 rad/s | 0.5453 rad/s | 0.7846 rad/s |
| transition | 66,560 | 0.7508 rad/s | 0.7874 rad/s | 0.8280 rad/s |
| above-rated | 357,013 | 0.7594 rad/s | 0.7917 rad/s | 0.8253 rad/s |

关键是后两类大量重叠：transition 与 above-rated 的转速中位数只差约 0.0043 rad/s。现有 PID 转速 schedule 也显示 condition 13 transition 的目标转速约 0.7858 rad/s，而 condition 14 above-rated 约 0.7871 rad/s；两者 P05–P95 范围重叠。[PID 转速参考：condition 11–14](../RL/data/pid_rotor_speed_reference_3_to_25.json#L140-L177)

转速区间混合也很明显：在 0.78–0.79 rad/s 区间，约 83.7% 是 wind-defined above-rated、11.7% transition、4.6% below-rated；在 0.75–0.76 rad/s 区间，约 52.0% 是 above-rated、18.2% transition、29.8% below-rated。固定转速阈值无法把三种控制模式干净分开。

### 3.2 按 condition 留一的转速阈值测试

最佳两阈值通常约为 0.7459 和 0.7779 rad/s（各 fold 的阈值范围约 0.7419–0.7494 和 0.7719–0.7794）。留一 condition 测试得到：

- overall accuracy：74.36%；
- balanced accuracy：63.10%；macro F1：63.09%；
- 三类 recall：below 85.11%、transition 28.60%、above 75.59%；
- transition precision 仅 15.41%。

混淆矩阵（行是真实 wind-defined 标签，列是转速阈值预测；顺序均为 below、transition、above）：

|  | 预测 below | 预测 transition | 预测 above |
|---|---:|---:|---:|
| 真 below | 206,250 | 21,148 | 14,932 |
| 真 transition | 2,627 | 19,036 | 44,897 |
| 真 above | 3,829 | 83,311 | 269,873 |

整体准确率被样本占比大的 below/above 类抬高；transition 仍有约 71.4% 被分到其它区。因此，**当前 raw 证据不支持用转速单变量替换 3-way wind partition**。这不表示风速标签正确，只说明 rotor speed alone 不能稳定复现它。

### 3.3 用户提出的超速倍率

raw 中最大 `I_RotorSpeed` 是 0.8750 rad/s。工程文件的 AEROINFO/PCOEFF 中有 OMEGA 约 0.79137 rad/s 的参考值，但该字段不是本次已确认的安全链额定转速设置。[工程 AEROINFO OMEGA](../bladed_env/15MW_rl.prj#L263-L265) 若仅以此值作试算参考，最大观测约为 1.1057 倍，$1.12$ 倍约 0.8863 rad/s，$1.20$ 倍约 0.9496 rad/s；本批 raw 没有达到这两个阈值的样本。**在确认工程/控制器安全链的 authoritative rated-speed 参数之前，不能把 OMEGA 参考字段直接当作正式 trip 基值。**当前 Python operating-state classifier 里看到的是运行/停机判定 0.5/0.4 rad/s，并非 1.12/1.20 倍超速链。[运行/停机阈值](../RL/utils/operating_state.py#L56-L88)

## 4. 结论与下一步

### 结论

1. 若“转速分区”是指以 rotor speed 单变量替换当前三类控制区：**不建议按当前 raw 结果直接切换**，尤其不能可靠分开 transition 与 above-rated。
2. 若目标是落实用户提到的超速保护：应单独设计/核验 `overspeed warning / algorithmic trip` 状态，按确认后的 $\omega_{rated}$ 计算 1.12×阈值；外层 1.20×保护链仍须按工程/DLL/硬件实际实现确认。不要把 safety trip thresholds 重新命名为 B4/BC operating regions。
3. 若风速测量的安装位置/时间同步不可靠，可研究用 rotor speed、real power、pitch（及其因果变化量）共同推断控制模式；但它是新的 classifier 设计，需先冻结输入、标签含义、滞回和 dwell，而不是只替换一个字段。

### 若后续批准改分类语义，需一起重建/测试的内容

1. **状态合同/分类器：**[OperatingStateConfig 与 classifier](../RL/utils/operating_state.py#L51-L89) 和 [分类逻辑](../RL/utils/operating_state.py#L205-L310)。升级 contract/schema 版本，定义 filtered rotor speed、阈值、初始化、滞回和持续确认；安全超速状态另立字段，不覆盖现有 operating-region 含义。
2. **训练标签与状态观测：**[state/action artifact builder](../RL/utils/state_action_artifact.py#L139-L254) 产出 region/optimization-state one-hot 和 coverage；重建 artifact/schema 与其 SHA。
3. **B4 teacher：**[B4 builder](../RL/build_region_aware_baseline.py#L88-L153) 用 classifier 将 action deltas 分配到各 region；[baseline runtime](../RL/utils/region_aware_baseline.py#L170-L215) 还根据 region/transition band 混合模型。须重新拟合所有区域并审查 transition coverage 和 blending，不能继续使用当前 265,791 / 66,609 / 357,600 样本划分。[当前区域样本数](../RL/data/region_aware_joint_baseline_state20_3_to_25_v3.json#L480-L481)
4. **其它共用 classifier 的标定/诊断：**[S2/U1 eligibility](../RL/build_s2_u1_calibration.py#L84-L105)、[PID rotor-speed schedule 的 eligible rows](../RL/build_pid_rotor_speed_reference.py#L61-L153)、[reward regional classifier](../RL/utils/reward.py#L543-L543)、[physical shadow 分区分组](../RL/utils/physical_load_shadow.py#L80-L105) 和 [动态裕量分组](../RL/utils/physical_load_margin.py#L215-L240) 都须审查并按新语义重算或重新审计。
5. **BC 与 checkpoint：**重建 B4 residual train/val targets 与 cache、BC config/resolved fingerprint；强制 BC-only 重训并做 raw_infer holdout。虽然 one-hot 宽度仍可能是 20，标签语义变化也必须使 observation/control contract fingerprint 变化，旧 BC checkpoint 不能只因张量尺寸相同而复用。
6. **活动 release/receipt：**当前 R2 SHA 和 receipt 不适用于新 classifier 语义。完成离线验证后应建立后继 release identity，重新 pin runtime/config/artifact SHA 和 receipt；R1/R2 均保留历史归档，不能原地重写授权或 receipt。新增阈值边界、hysteresis、扰动/滞回、跨 condition holdout、raw_infer 冻结验证、每区样本覆盖与安全 trip tests。

**当前决定：**完成了 raw-only 可分性分析；未改分类器、工件或 release。建议先做冻结条件下的离线多信号分类器/时序对齐实验，再据 raw_infer 结果决定是否升级语义；不应把 1.12/1.20 倍安全停机线直接用作三个训练分区阈值。
