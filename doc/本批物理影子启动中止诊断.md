## 2. 风速来源：不能把变量名当作物理定义

当前 [DLL源码](../bladed_env/udptest/udptest/controller.cpp#L1095)将 `I_AverageWindSpeed` 赋值为 `GetNominalHubFlowSpeed(turbine_id)`。本机 [Bladed 4.8 API说明](../bladed_env/BladedAPI/4.8/ExternalControllerApi.h#L1821-L1826)定义为轮毂位置自由来流所建模的轮毂风速，且没有实际机舱风速仪／皮托管建模；**不是转子盘平均风速**。

因此“转子盘测量必随控制几何改变”不能作为已证明的根因。轮毂位置／结构变形是否影响该API在本次工程中的取样、旧PID CSV是否同一采集映射、Windows实际加载DLL是否对应此源码，当前证据均不能闭合。即使风文件与种子相同，也需先核定这个量是否真是控制无关的外生身份信号，不能默认PID与RL的响应相关信号全程逐点相同。

[600 s配对参考](../RL/data/paired_pid_power_load_reference_3_to_25_600s_v2.json)明确保存PID CSV的 `Time` + `I_AverageWindSpeed` 全轨迹，按同case／同seed／同窗配对。本次实算wind8原始CSV SHA与entry一致：`2e7bad3104dab0d85ca7b8175b635519b751405c0c110339681292e0ba82dbe5`。Linux参考未出现已发现的文件错配；但这不验证Windows风文件、工程或种子。

## 4. 已复现并修复的独立清理缺陷

用户报告的次级错误为 `[Cleanup] physical shadow summary failed: ValueError`。在临时目录重现原实现得到：`ValueError: could not convert string to float: 'physical_fir_v2'`。

根因：[日志汇总接口](../RL/utils/logger.py)原先对所有顶层值执行 `float(value)`，但物理汇总含字符串 `backend`、布尔标志、嵌套计数器和receipt列表；第一个backend值即失败，尚未打开输出文件。**不是NaN／Inf或未完成slot导致汇总崩溃。**

修复范围：

- [日志接口](../RL/utils/logger.py)：保留结构化身份、布尔和整型，递归转换NumPy值／数组；非有限浮点用JSON `null`表示未知，`allow_nan=false`；先序列化校验，避免不支持的对象截断目标。
- [训练清理](../RL/train_rl.py)：输出异常类型及具体文本；close失败时在非最终汇总中保留错误文本；不替换主异常。
- [日志回归](../RL/tests/test_logger.py)验证嵌套结构／未知数值／写前校验；[影子回归](../RL/tests/test_physical_load_shadow.py)验证64帧后身份异常触发ExitStack清理，主异常对象不变，真实worker部分记录生成有效JSON，无完整slot receipt、无资格提升。
- 定向67项PASS；`wind`环境、BLAS线程1的全量unittest discovery：368项，1 skipped，其余PASS，99.241 s。含本机FakeUDP fixture，非真实Bladed运行。

本批已有配置、实验文件未补写或覆盖；12个文件的修改前后SHA一致。旧批没有足够worker计数／待成熟窗口信息，不能凭3行记录伪造追补最终汇总。

附带身份字段：影子 `run_id=60972578d6274db6aa1cfda115772187` 来自 `PhysicalShadowCore` 自行生成的UUID；Windows `BLADED_RL_MANUAL_BATCH_RUN_ID` 只管理DLL手工队列状态，并未传入该core。线上训练提交明确传 `actor_policy_sha256=''`，同时记录版本0。这两个字段的差异是现有接线行为，不是本次t=1.28中止的原因；本轮不改其语义。
